# 《年复一年》Seedance 2.5 独立提示词标准 V0.1

- **日期：** 2026-10-23
- **版本：** V0.1
- **状态：** 待验证草案（DRAFT / PENDING_SKILL_VALIDATION）
- **适用范围：** 将《年复一年》的统一导演设计转译为 Seedance 2.5 专用视频提示词，并对输入、生成与验收建立统一规则
- **配套文件：** 《导演决策与审批规则》、协作工作流与分工、Seedance Skills 安装记录与双模型提示词工作流
- **重要声明：** 本文是基础规则草案，不代表三个 Seedance Skill 已通过实际运行验证，也不代表任何未批准的镜头、机位、静帧或视频生成方案已获导演批准。

## 一、目标与适用边界

本标准用于减少以下问题：

1. 导演意图、静帧、提示词和生成结果之间发生偏差。
2. 提示词只描述剧情，没有明确动作顺序、摄影机运动和镜头结束状态。
3. 参考图或参考视频的职责不清，导致错误继承机位、姿态、背景或动作。
4. 人物、服装、家具、道具在生成过程中发生非预期变化。
5. 单镜头可看，但与前后镜头的动作、空间、光影或剪辑节奏不连续。
6. 生成失败后不断增加否定词，却没有定位真正的失败原因。

本标准不预设 Seedance 能严格执行每一个时间戳、运镜参数或细节。平台支持的时长、参考素材数量、首尾帧方式、视频引用方式等，必须依据实际使用的平台与模型版本验证；未经验证的能力不得写成硬性事实。

本标准不取代导演审批。Skill 输出、提示词检查或技术验证均不自动构成创作批准。

## 二、三层设计体系

### 2.1 统一导演设计

Seedance 与本地 H3 共用同一份导演设计依据，至少明确：

- 镜头的叙事目的和情绪功能。
- 镜头开始时的人物、场景与道具状态。
- 人物动作的原因、顺序、关键变化和结束状态。
- 景别、机位、运镜、焦点及其叙事动机。
- 场景空间、人物走位和道具物理关系。
- 与前后镜头的剪辑接口。
- 不可改变的约束、可调整的变量及待导演确认事项。

统一导演设计是创作依据，不应不加区分地整段复制为任一模型的最终提示词。

### 2.2 Seedance 专用转译

将已确定的导演设计转译为适合实际 Seedance 输入方式的提示词，重点是参考素材分工、可观察的动作因果、镜头运动、时间节奏、连续性约束和明确的结束状态。

最终提示词应突出最影响镜头成立的关键动作，不要把所有导演讨论和背景资料无差别堆入正文。不得擅自改变已确认的剧情、人物、空间或导演选择。

### 2.3 H3 专用转译

本地 H3 继续使用独立的提示词规范、工作流设置与技术约束。Seedance 的提示词不得未经验证直接复制给 H3；H3 的执行经验也不得未经适配直接当作 Seedance 的硬规则。

## 三、单镜头设计必填项

每个镜头应有唯一编号和独立记录。

| 字段 | 必须明确的内容 |
|---|---|
| 镜头编号与版本 | 场次、镜头号、导演设计版本、模型提示词版本 |
| 叙事目的 | 本镜头要让观众看到、理解或感受到什么 |
| 开始状态 | 人物位置、姿态、视线、手部状态及道具位置 |
| 核心动作 | 动作起因、执行过程、关键变化与完成状态 |
| 人物约束 | 身份、年龄、面部、发型、服装与表演强度 |
| 场景约束 | 家具、墙窗、通道、灯位和空间拓扑 |
| 摄影设计 | 景别、机位、角度、运镜、焦点与构图 |
| 时间节奏 | 动作顺序、停顿、速度变化及预计时长 |
| 参考素材 | 每张图、每段视频的用途、优先级与版本 |
| 结束状态 | 人物、道具、构图和摄影机的目标状态 |
| 剪辑接口 | 与前镜如何衔接、如何进入下一镜 |
| 验收条件 | 成功标准、关键失败条件与返修方向 |

不适用的字段可标为“不适用”；影响剧情或镜头执行的未决项必须标为“待导演确认”，不能交由模型自行决定。

## 四、参考素材分配规则

每份正式提示词必须附带参考素材清单，并标明文件或资产编号、版本、职责、验收状态和使用许可状态。

### 4.1 参考图

每张参考图必须说明：

- 负责锁定什么：人物身份、服装、场景拓扑、道具外观、构图、首帧或结束状态。
- 不负责锁定什么：例如仅用于身份，不代表其原图服装必须继承。
- 哪些元素允许变化，哪些元素必须保持。
- 图片是否已实际检查、是否已通过视觉验收、是否获准用于视频生成。

不得默认一张参考图能同时承担全部约束。存在冲突时，必须明确优先级；关键冲突未解决前不得正式生成。

### 4.2 参考视频

使用参考视频时，必须说明它负责提供哪一类参考，例如人物动作节奏、身体重心变化、摄影机运动或环境动态，并注明不应照搬的内容。

动作参考视频不得自动覆盖已批准的人物身份、服装、场景拓扑或剧情事实。

### 4.3 首帧与尾帧

使用首尾帧前，检查：

1. 两张图是否属于同一镜头合理的起止状态。
2. 两者之间能否通过连续动作实现，不需要道具瞬移、人物回退或不可能的身体运动。
3. 机位和构图差异是否适合连续生成；若属于不同机位，是否应该剪辑切换而非强行变形。
4. 当前平台和模型版本是否支持计划采用的输入方式。

静帧只能证明某一时刻的画面状态，不能单独证明中间运动成立。

## 五、动作因果与可观察状态

### 5.1 动作结构

优先按以下结构描述核心动作：

**初始状态 → 动作触发 → 可观察的执行过程 → 状态变化 → 结束状态。**

示例：人物因需要整理白色下柜而起步，从沙发区域沿茶几外侧的可通行区域前进，绕过桌子后减速，最后停在柜前。该例仅说明动作描述结构，不批准具体机位、时长或静帧。

### 5.2 动作必须可观察

不要只写抽象意图，应写明观众能看到的动作证据：

- “感到疑惑”可具体化为短暂停顿、视线落点和克制的眉眼变化。
- “拿起篮子”应说明手与篮沿的接触、篮子离开原支撑面、移动方向及落地或放置后的稳定状态。
- “盒子逐渐显露”应说明哪个遮挡物移动、盒子是否固定、可见部分如何变化。

### 5.3 避免矛盾与过载

提示词不能同时要求互相冲突的状态，例如手已松开篮子却又持续扶住篮子、盒子固定不动却又自行移动、人物尚未接触柜门却已经完成开门。

一个镜头应突出少量关键动作。如果动作过多、因果难以表达或无法在计划时长内完成，应回到导演设计阶段判断是否拆镜；不得只靠堆叠更多指令掩盖结构问题。

## 六、摄影机与镜头语言

每个镜头应明确以下适用项：

1. **景别：** 远景、中远景、中景、中近景、近景或特写。
2. **机位：** 摄影机所在侧、拍摄高度、方向和视角。
3. **运镜：** 固定、推拉、摇摄、横移、跟随等；说明起点、方向、幅度、速度倾向和停止位置。
4. **焦点：** 主要观察对象，以及是否需要焦点转换。
5. **构图：** 主体位置、运动方向、画面留白和重要空间关系。
6. **节奏：** 镜头保持、运动、停顿和结束之间的关系。

固定机位是有效的导演选择，不应为了增加“电影感”而无理由添加运镜。运镜必须服务于叙事、空间交代或观众注意力，不能替代不清晰的动作设计。

摄影机参数应写成对模型有意义的可执行描述；未经测试的镜头数值或模型能力不设为统一硬性要求。

## 七、时间线与节奏

提示词应明确动作先后和节奏变化，必要时使用阶段或时间范围组织：

- 开始：建立人物和场景状态。
- 中段：执行主要动作及关键变化。
- 结束：到达明确状态，为下一镜头提供剪辑接口。

时间戳属于提示模型理解动作顺序的辅助表达，不应在未经测试时被视为严格逐帧约束。时长应根据动作复杂度、移动距离、停顿和情绪节拍决定，不得为追求提示词简短而压缩已经确认的叙事时长，也不得让人物为了填满时长重复无意义动作。

具体时长范围、分段方式和平台可接受的时间表达，留待实测校准。

## 八、场景、身份与道具连续性

### 8.1 场景空间

每个镜头必须继承已批准的场景母版：

- 家具、墙窗和主要空间关系不变。
- 人物路径符合真实通行空间。
- 摄影机所在侧与透视关系一致。
- 灯位和主要光源方向符合场景设定。
- 不擅自增加或删除关键家具、门窗、灯具及人物。

### 8.2 道具物理关系

对重要道具记录：

- 起始位置、朝向和支撑状态。
- 谁在何时接触它。
- 通过什么动作改变其位置或状态。
- 移动方向、落点和结束状态。
- 下一镜头需要继承的状态。

涉及遮挡、取放、开合或接触时，必须确认动作在物理上成立。道具不得无原因移动、复制、变形或改变尺度。

### 8.3 人物身份与服装

人物面部、年龄、发型和服装按已批准的正式资产约束执行。未经批准的生成候选不得当作正式身份或场景资产。身份参考与服装参考职责不同，应分别标明。

## 十、生成前验收

正式生成前逐项检查。

| 验收项 | 通过标准 |
|---|---|
| 叙事目的 | 能明确说明本镜头存在的必要性 |
| 动作因果 | 每个关键动作有合理起因和可观察的完成状态 |
| 初始状态 | 人物、道具和场景起点明确 |
| 动作顺序 | 不存在矛盾或不可能连续完成的动作 |
| 摄影设计 | 景别、机位、运镜及焦点意图明确 |
| 参考素材 | 每份素材职责清楚，关键冲突已解决 |
| 空间关系 | 人物走位、家具和通道在物理上成立 |
| 连续性 | 与前后镜头的起止状态兼容 |
| 资产状态 | 必需素材已通过视觉验收并获准使用 |
| 技术可执行性 | 当前平台输入方式与关键参数已确认 |

**放行规则：** 若动作逻辑、关键参考素材、场景拓扑、人物身份或剪辑接口存在未解决的关键问题，不进入正式生成。非关键风格细节可以列为观察项，不必无限期阻塞低风险试拍。

## 十一、生成后验收

生成后同时检查画面质量与叙事执行结果。

| 维度 | 主要检查内容 |
|---|---|
| 剧情执行 | 是否真正完成预定动作，而不只是出现相似画面 |
| 人物身份 | 面部、年龄、发型和服装是否稳定 |
| 动作逻辑 | 是否出现重复、回退、瞬移、穿模或不合理接触 |
| 空间连续性 | 家具、通道、机位和透视是否非预期变化 |
| 道具连续性 | 道具是否正确移动、显露、拿取或放回 |
| 运镜执行 | 摄影机是否符合设计，是否出现无动机运动 |
| 时间节奏 | 关键动作是否完整，停顿是否合理 |
| 光影质感 | 是否符合场景母版，是否出现明显塑料皮肤或异常染色 |
| 剪辑接口 | 结束状态能否自然连接下一镜头 |
| 声音 | 若包含声音，环境声、对白与动作声音是否符合画面 |

项目内部的临时判定规则：

- **关键项不通过：** 镜头不通过，不能被其他维度的优点抵消。
- **关键项通过但存在可修正缺陷：** 进入针对性返修。
- **关键项通过且整体符合导演意图：** 提交用户最终批准。

关键项至少包括剧情核心动作、人物身份、空间物理关系、重要道具状态和剪辑接口。V0.1 暂不规定评分权重，待测试后确定。

## 十二、失败分类与最小化迭代

| 失败类别 | 典型现象 | 优先修正方向 |
|---|---|---|
| 剧情理解失败 | 做了其他事情，关键事件没有发生 | 缩小动作目标，强化因果与终点 |
| 动作执行失败 | 动作开始但未完成 | 明确接触、位移、停止等状态 |
| 空间错误 | 人物走错区域或家具变化 | 修正空间参考与走位设计 |
| 道具错误 | 盒子自行移动、复制或尺度改变 | 检查起止状态图和物理动作 |
| 身份漂移 | 面部、年龄或服装改变 | 检查参考职责与身份约束 |
| 运镜错误 | 无理由推拉、摇移或跳变 | 简化运镜，明确运动终点 |
| 节奏错误 | 重复动作、动作过快或停顿异常 | 调整动作数量和节奏安排 |
| 风格错误 | 光色、肤质或景深偏离母版 | 针对性修订风格约束 |
| 剪辑不连续 | 结束状态无法连接下一镜 | 检查相邻镜头状态兼容性 |
| 平台执行问题 | 输入失败、参数不支持或生成异常 | 核实实际平台功能与输入要求 |

迭代规则：

1. 每轮优先修正一个主要失败原因。
2. 不同时无依据地修改身份、机位、动作、光影和构图。
3. 保留失败视频、提示词版本、输入素材和审查结论。
4. 静帧本身不符合物理逻辑时先修静帧，不用视频提示词掩盖问题。
5. 区分导演设计问题、提示词转译问题和模型能力限制。
6. 不以不断增加否定词替代失败诊断。

## 十三、三个 Skill 的协作假设（待实测）

以下是拟验证的职责分工，不是已经证明的 Skill 能力。

### Seedance 2.5 Director

预期职责：叙事意图、场景上下文、人物关系、镜头连续性和导演审批边界。

### Seedance Shot Design

预期职责：将导演意图转化为可审查的镜头设计，包括景别、机位、运镜、表演动作、时间节奏和剪辑接口。

### Seedance 2.5 Prompt Skill

预期职责：将已确认的镜头设计转译为适合 Seedance 的提示词，整理参考素材职责和执行约束。

协作原则：

- 前一环节的输出是后一环节的依据，不代表自动批准。
- 提示词环节不得自行改变已批准的剧情和镜头设计。
- 分镜环节不得未经确认改变正式人物、场景或道具状态。
- 三个 Skill 输出冲突时，应回到对应职责层解决，不直接拼接冲突指令。
- 必须通过实际触发测试确认各 Skill 的行为、输出质量和边界，再正式确定职责分工。

## 十四、V0.1 实测校准计划

### 统一测试用例

使用《年复一年》Scene01-P02：老年妻子从沙发区域沿茶几外侧可通行区域走向右侧白色下柜，继承已确认的客厅空间拓扑和人物资产，最后停在柜前，为下一镜开柜提供动作接口。

该用例仅用于测试，不提前批准尚未确认的机位、首帧、运镜或具体时长。

### 测试项目

1. 三个 Skill 是否能被当前 Codex 环境发现并实际触发。

## 十五、版本升级原则

V0.1 只建立基础规则，不代表所有条款已获得 Seedance 实测支持。

三个 Skill 实际验证后，应根据证据修订：

- 删除无法执行或无实际价值的规则。
- 补充测试中发现的缺项。
- 区分通用导演要求与 Seedance 专属执行要求。
- 明确哪些规则已验证有效，哪些仍是假设。
- 记录测试镜头、输入版本、输出结果和修订理由。

只有当 Skill 调用、提示词输出以及至少一次真实视频试拍的关键验收均有证据支持后，才考虑升级为正式 V1.0。

**最终目标：建立可复用、可审查、可迭代的 Seedance 制作规范，而不是一份看起来完整、却未经实际生成验证的提示词模板。**
