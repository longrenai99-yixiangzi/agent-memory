## 使用说明

本清单不按天安排。用户可按自己的节奏一次完成或分批完成。Codex 开始执行时，必须先盘点已有素材和本地工作流能访问的文件，逐项将状态更新为“已有可用 / 已有待审查 / 需补充 / 不需要”，不得让用户重复制作已有合格资产。

### 状态定义

- **待盘点**：尚未确认现有素材是否可用。
- **用户提供**：素材内容由用户真实记忆、真实人物或真实场景决定。
- **待生图**：画面构图由导演方案决定，可由用户按提示词生成。
- **待审查**：文件已提交，但尚未完成视觉审查。
- **已通过**：已通过技术检查和必要的导演审查。
- **待确认**：需要用户决定身份、事实或创作取舍。
- **不需要**：经镜头方案确认，该资产没有必要。

| ID | 素材 | 用途 | 验收标准 | 初始状态 |
|---|---|---|---|---|
| B01 | 电视柜柜内初始状态首帧 | 建立整理开始前的空间和道具状态 | 收纳篮位于前方；旧盒子被完全遮挡，任何边角、盖沿、顶部或轮廓均不可见 | 待生图 |
| B02 | 妻子拿出收纳篮后的柜内状态关键帧 | 表现发现发生的物理条件 | 盒子此时才首次显露；柜格、篮子和盒子位置可信 | 待生图 |
| B03 | 妻子发现盒子的中景/中近景关键帧 | 表现日常动作突然减缓与疑惑 | 不演成认出旧物；眼神、手部、身体姿态支持“发现了不该在这里的盒子” | 待导演方案 |
| B04 | 盒子的妻子准主观视角特写 | 作为视线匹配剪辑的短暂信息镜头 | 机位高度、方向与妻子蹲姿视线相容；不是随意的产品展示角度 | 待导演方案 |

## 必须先由 Codex 完成的工作（不需要用户先做）

1. 盘点第一场全部已有图片、视频、剪辑版本与任务记录。
2. 为每项已有素材记录路径、用途、版本、是否通过审查，以及能否复用。
3. 对照当前导演共识，将需求分为“已有可用 / 已有待审查 / 需补充 / 不需要”。
4. 与 ChatGPT 的整段动态导演方案对齐后，确定 B 类和 C 类任务的最终数量，不能在方案未定稿前要求用户盲目生成全部关键帧。
5. 为每项真正需要用户生成的图片提供独立、完整、可直接复制的提示词，并列出要上传的参考图、每张图的作用、禁止项、保存路径和验收标准。
6. 建立任务 JSON；将用户提供的真实参考素材与创作生成素材分开标记。
7. 对关键图片执行双层审查：技术完整性由 Codex 检查；构图、表演和情绪由 ChatGPT 审查；需要真实信息或创作取舍时交由用户确认。

## 第一场的创作硬约束（当前已确认）

- 整体情绪温暖、自然、克制，不刻意煽情。
- 妻子原本只是在整理电视柜；收纳篮移开后才发现柜格深处的旧盒子。
- 收纳篮移开前，旧盒子必须完全不可见，任何边角、盖沿、顶部或可识别轮廓都不能露出。
- 妻子发现时主要是疑惑和好奇，想知道为什么盒子会在这个不寻常的位置，并产生打开它的念头；不能提前演成认出旧物或已经被回忆打动。
- 镜头重心是妻子的行为和情绪变化，不是盒子本身。
- 不再默认使用从面部特写慢摇到盒子的复杂运镜；优先研究视线匹配剪辑，但最终镜头顺序由完整动态方案确认。
- 每个镜头必须说明人物如何动、摄影机如何动或为何固定、关键动作时机、切入/切出方式及前后镜头的空间连续性。
- 只定大致节奏与关键时机，保留自然表演和剪辑调整空间。

## 第一场试点完成标准

第一场只有在以下条件全部满足后，才视为工作流试点成功：

1. 导演意图与动态镜头方案已由用户确认。
2. Codex 提供完整素材清单，且用户不需要猜测图片怎么准备。
3. 关键图片实际可读取并经过相应审查。
4. H3 提示词能追溯到已批准的镜头方案与指定参考资产。
5. 生成结果经过单镜头和整段剪辑双重检查。
6. 失败原因、修正变量和可复用经验已记录。
7. 项目状态和资产索引已更新，且原始文件没有被覆盖。

第一场试点通过后，再把已验证的流程扩展到第二场及全片。第二场的咖啡店照片转场目前只保留创作线索，不提前批量生成。
