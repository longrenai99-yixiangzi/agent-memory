## 3. 一次性完成 C06→结尾的镜头组设计

**以整场戏和相邻镜头组为设计单位**，并考虑全片镜头语言递进。为每个镜头建立一条数据记录，字段至少包含：

- shot_id、scene_id、script_ref、剧情时刻、镜头叙事职责、情绪目标；
- 场景工程与世界状态、具体人物/道具 ID；
- 拍摄景别、构图与机位类型、世界坐标 (x,y,z)、目标点、摄影机朝向、焦距/视角、机高、是否固定/运动；**坐标只有 Blender 验证后才能填为“已测”**；
- 角色脚点坐标、面朝方向、视线目标、动作起止状态与可见状态；
- 预计帧数/时长、动作节拍、入点出点、过渡方式、画内/画外声与声音桥；
- 前镜收尾接口、后镜开场接口、运动方向、视线关系、轴线规则；
- lighting_state_id、palette_id、reference_image_id、审批状态和问题级别。

**每个切点必须有剪辑动机**，例如动作匹配、视线连接、信息揭示、空间建立、声桥或有意的时间省略。坚决避免重现本项目已有问题：擦桌→叠毛毯缺行动连接、丈夫回头→妻子突然近身、走路→突然静止、人物瞬移及声音突断。可以有意跳切，但必须把叙事理由写清，而不是让素材意外断裂。

**分镜递进原则：**第一次异常克制，随后异常逐级强化，强交汇遵照现行剧本；尾声按照情绪归宿处理。禁止为“电影感”擅自创造新的猫声、异常光源、角色或剧情。

输出：planning/02_full_shotlist.csv、planning/02_shot_groups.md、planning/02_edit_interfaces.csv、planning/02_runtime_budget.md。

## 4. 人物表演必须写成可执行动作（强制门槛）

**禁止只写“开心、紧张、惊讶、疑惑、悲伤”等情绪标签。** 对每个有表演的镜头，必须写具体、可观察、可预演的变化，至少依据实际动作涉及：
1. 眼睛：注视目标、眼球先后转移、眨眼/停顿；眉毛、眼睑；
2. 面部：嘴角、嘴唇、下颌、面部肌肉的轻微变化；
3. 头颈与躯干：头转角度、肩膀、呼吸、姿态、重心；
4. 四肢/道具：手如何抱衣服或触碰物品、脚步何时放慢或停下；
5. **动作时序**：先后顺序、预计时间或帧区间、幅度、起态/终态。

不得为了填表强加所有部位的动作。没有变化可标“保持自然”。风格以克制、生活化为主，遵循安装的表演 Skills。

示例（仅说明书写精度，不是对某个镜头直接下导演决定）：

> 抽象句「妻子疑惑地看向沙发」不合格。  
> 可执行句「行走过程中视线先向沙发偏移；下一拍脚步减速；头部小角度跟进，眉心略收紧，双臂抱衣状态保持；身体尚未完全转身，短暂停住观察」。  
> 具体角度/拍数应根据该镜头站位、剪辑点与导演审核再定。

输出：planning/03_actor_beats.csv、planning/03_actor_performance_notes.md。若缺少可用 rig，Blender 用头部/身体朝向或文本叠加表示微表情的代理状态；**不可把代理预演冒充真实面部动画**。

## 5. 全片灯光、色彩、气氛连续性（强制门槛）

### 5.1 先继承正式规范，绝不自创“最终调色”

实际读取现有：《客厅夜景电影色彩与成像使用规范 V1.0》（2026-10-30）及《电影灯光与影调设计规范 V1》，连同已批准中性场景母版与色卡/参考帧的真实可用版本。

已知分段指导：
- **清洁/整理阶段**：明亮、自然、中性，不要过暖；用于呈现生活秩序。
- **夜谈/正常夜景**：保留中性材质、克制的室内局部暖光与窗外深蓝冷夜；不是全局套蓝橙滤镜。
- **异常/雨夜交汇**：仍以真实灯具、雨夜环境及剧情时间为依据，允许不同强度的明暗递进，但不得创造没有来源的光斑或随镜头换灯位。
- **C6 调亮参考**：仅作临时电影光影方向，**不是**最终空间、调色或 LUT 母版；近期图片未必真正上传仓库，必须核对本机可用文件。
- **尾声/其它房间**：继承整片自然主义和成像质感，但按场景真实光源另建灯光状态，不能照搬客厅夜景色卡。

现有夜景六色 HEX（#AF8B73、#A68457、#5A5343、#713E22、#062D4A、#261B14）仅为**概念性参考**，不代表从 C6 图精确测得的颜色，不得冒充已制作的 LUT、不得把颜色卡片画进场景。

### 5.2 可执行的场景/镜头色彩约束

为每个 **scene + lighting state** 建立：
- scene_id / world / day-night / lighting_state_id；
- 主色用途、冷暖关系、曝光区间的定性目标、角色脸部可读性；
- 已存在的灯具/窗的世界位置 ID、开关状态、方向、影响区域；
- neutral_master_ref、cinematic_ref、palette_ref，各引用必须真实存在，分清几何权威与风格参考；
- 同一场景前后反打的材质固有色与受光连续性检查。

在 Blender 白模阶段至少建立能看出**亮暗层级和灯源方向**的低成本预览；复杂电影化色彩暂以可追溯的 lighting/palette ID 和参考对照表达，不要求高成本渲染。生成场景参考图的提示词未来必须明确空间母版、光源位置、天气、时间、材质、影调、成像与禁改项。

连续性验收包括：灯位不漂移、不同机位物体固有色不跳、相邻镜头曝光/白平衡无无因跳变、夜景阴影有细节、皮肤不被大面积橙蓝染色。**色卡只能校方向，不能单凭 HEX 自动保证镜头一致。**

输出：look/04_look_bible.md、look/04_lighting_registry.csv、look/04_color_state_map.csv、look/04_reference_status.md。

## 6. Blender 自动建机位、自动检查、必要时自行修正

### 6.1 可重复运行

在本机项目中创建独立输出目录（示例：output/fullfilm_previs_v01/），以及 scripts/ 下的自动脚本。先用最小样本验证 Blender 可打开副本、读取对象、创建并渲染摄影机、写出文件。**验证的是脚本运行能力，不以单个镜头审美通过替代全片审核。**

每个新镜头必须创建唯一命名摄影机，例如 CAM_SC01_C06、CAM_SC02_C01；人物代理使用统一角色 ID；镜头元数据写入 JSON/CSV 和 Blender 对象自定义属性，保证能双向定位。

### 6.2 机位检查规则

自动或半自动完成以下检查，失败时尝试限次调整并保留日志：
- 摄影机不在墙/门/家具内部，不穿墙；需要特定切面/隐藏墙时必须标为预演技术措施；
- 角色关键脚点在可通行地面，运动不穿过家具、墙与封闭门洞；
- 主体在预定景别内，人脸/手部/关键道具的可见范围符合叙事任务；
- 视线目标可达，反打空间方向、180°轴线与运动方向合理；故意越轴须说明转换依据；
- G/E/X 边界、A/B 可见条件及既有批准路线不被破坏；
- C05→C06 等关键接口连续，脚点、动作、手持道具、朝向可追溯；
- 静态截图不能验证的动态问题必须标“待动态验证”，不谎称已通过。

程序能检查碰撞、投影、可见性、数值连续性；**不能凭自动评分宣布构图、情绪、表演、电影美感已获导演批准**。无法确定优选机位时可生成 2 个明确标号的候选，但不得无限展开。

### 6.3 预演表现优先级

优先用已有可用动作/Rig；其次用代理人物关键帧（行走、转头、停止、抱猫等）表达真实空间关系；再其次用静态参考帧配时间与动作说明叠字。**没有可用人物 Rig 时不伪造自然微表情动画**。整条片必须能连续播放，缺项可使用醒目 PLACEHOLDER。

输出：blender/fullfilm_previs_v01.blend（或等效分场副本 + 总索引）、scripts/、cameras/、frames/；每一镜至少一张**真实 Blender 摄影机视图**，另有镜头元数据 JSON、必要时俯视图与遮挡检查图。

## 7. 自动拼接完整可播放预剪

- 仅拼接 **SC01-C06→结尾** 已产生的镜头预演；现有 C01—C05 属衔接参考/时间预算，**不得悄悄重生成或覆盖**。可额外输出带 C01—C05 现有素材的完整全片装配版，必须标清哪些是既有视频、哪些是预演、哪些占位，且不得让旧素材的分辨率/帧率自动决定每镜摄影方案。
- 镜头时长依据具体动作/对白与叙事节奏设计；先核对原视频媒体属性与目标交付帧率，统一输出 CFR（固定帧率）；剪映使用 HH:MM:SS:FF，明确 fps，右端点不含；同时输出以毫秒计的时间表。
- 首轮预剪允许临时字幕、时间码、镜头 ID 和静帧停留，但**不得默默用一个静帧冒充自然动作**。
- 用基本房间底噪/对白占位维护跨切点声音连续，预留 J-cut/L-cut 标记；禁止让每段视频的独立环境声切换造成突兀归零；禁止自加猫叫及未经剧本允许的事件声音。
- 若 ffmpeg 或其它编码工具不在本机，记录缺失，优先使用 Blender VSE / 本机已安装工具组合导出；不得伪称视频存在。

输出：edit/05_previs_C06_to_end_v01.mp4、edit/05_timeline.csv、edit/05_shot_assembly.json、edit/05_audio_bridge_notes.md；如可行额外输出 edit/05_fullfilm_assembly_with_existing_v01.mp4。

## 8. 自动验收、问题分级与交付

### 8.1 自动验收标准

逐镜、逐场、全片三级检查：
- **P0 阻断**：剧本事件错误、错误世界/交汇规则、母版被覆盖、身份严重混乱、工程损坏、文件不存在却声称存在；立即隔离，不发布假成果。
- **P1 重要**：镜头穿墙、人物/道具位置不对、切镜产生不合理瞬移、关键视线看错、同场光源方向矛盾、表演仅有情绪词、相关 Skill 未读取或无应用证据；先自动修正，修不好用故障标记与占位继续。
- **P2 可延后**：构图微调、动作细腻度、暂缺面部 rig、电影感光学成像未完成；标注待导演审核，不阻断全片粗剪。

镜头验收必须核对：剧本职责、动作可执行性、景别与构图、轴线与机位、连贯性、实际文件可读、色彩/光源状态、Skill 规则映射。

### 8.2 最终六类交付物（缺一项必须说明）

1. **完整镜头设计与时间线**：C06→结尾的全部分镜表、叙事逻辑、剪辑接口与帧数。
2. **全部摄影机参考画面**：每镜实拍机位输出图，标记代理或占位。
3. **可修改 Blender 工程与脚本**：带摄影机、人物脚点、灯光 ID、对象/镜头映射，支持增量批量重跑。
4. **一条可播放的整段预演视频**：从 C06 到全片结尾；可选全片装配版。
5. **缺失资产与未解决问题报告**：按 P0/P1/P2 分级，写明来源、影响镜头、修复方案、是否需要导演决策。

### 8.3 运行完成后的报告格式

必须明确给出：
- 完整剧本版本、Blender 母工程及工作副本路径、已扫描 Skill 数量与有效数量；
- 覆盖场次/镜头数、实际产出帧图数、实际输出视频文件/分辨率/帧率/时长；
- 剧情预算时长与实际预剪时长的差异；
- 可自动通过的技术检查项数，尚未通过的 P0/P1/P2 数量；
- 缺失/待批准的资产、导演必须决定的少量问题；
- 一条复跑入口命令（Windows 11 PowerShell 实际可执行，**不能虚构本机路径**）。

Windows 示例结构（**仅模板，实际执行需用本机真实路径替换并检查文件存在**）：

~~~powershell
$BlenderExe = "C:\实际路径\blender.exe"
$BlendFile = "D:\实际项目路径\working_copy.blend"
$Script = "D:\实际项目路径\scripts\build_previs.py"
if (!(Test-Path $BlenderExe) -or !(Test-Path $BlendFile) -or !(Test-Path $Script)) { throw "缺少 Blender、工程或脚本，请核查真实路径" }
& $BlenderExe --background $BlendFile --python $Script
if ($LASTEXITCODE -ne 0) { throw "Blender 执行失败：$LASTEXITCODE" }
~~~

## 9. 工作效率及安全边界

- 一次性推进后续全部镜头初稿；不要逐镜头暂停等待确认。
- 普通问题自动重试有上限（默认每镜最多两轮有目标的修正）；失败即标记，避免无限调机位或无限生成。
- 工作过程可以分批运行、断点续跑，但每次都更新任务状态和输出文件，避免重复生成已成功的部分。
- 对 C05 最新接口、缺失 Rig 或不可见的已批素材，**不能猜测**；优先保持可追溯占位。
- 禁止未经允许删除、覆盖已批准工程、正式素材、现有文档；禁止上传素材原件、个人信息、密钥或 AI 生成视频到 GitHub，除非后续明确授权。
- **本任务书的发布不是“Codex 已经执行”、不是“分镜已批准”**。只有真实在本机跑出有据可查的文件，并经用户导演集中审核，才能进入后续正式 AI 视频批量生成阶段。
